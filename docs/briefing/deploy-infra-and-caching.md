# Deploy, Infra, and Caching

Elastic Beanstalk deploy semantics, the Cloudflare / RapidAPI edge topology, HTTP caching, AWS quirks, the proxy-auth chain, and GHCR image publishing. Split from `what-will-surprise-you.md` 2026-07-28 (Tier-3 budget).

- **`Rolling` on Elastic Beanstalk does NOT mean batched deploys here — two different batching namespaces get conflated, and it has now bitten three documents.** Application deploys use `aws:elasticbeanstalk:command`, where `DeploymentPolicy = "Rolling"` but `BatchSize = "100"` / `BatchSizeType = "Percentage"` puts the whole fleet in ONE batch. The reassuring `MaxBatchSize = 1` / `MinInstancesInService = 2` / `RollingUpdateType = "Health"` values live in a _different_ namespace, `aws:autoscaling:updatepolicy:rollingupdate`, which governs ASG **instance replacement**, not deploys. Quoting the second while talking about the first is the trap: ADR 004 (said `AllAtOnce` outright until the 2026-07-26 amendment), ADR 001, and this briefing line all fell into it. Also note `RollbackLaunchOnFailure = "true"` is `aws:elasticbeanstalk:control` — it covers environment **launch** failure, not a red post-deploy check. 100% Spot; health check targets `/health`. Deploy-window duration is unmeasured.
- **ADR 024 proxy-auth secret chain**: 1Password Voder vault item `Addressr RapidAPI Proxy Secret` → GH repo secrets `TF_VAR_PROXY_AUTH_HEADER`/`TF_VAR_PROXY_AUTH_VALUE` → Terraform `dynamic "setting"` blocks in `deploy/main.tf` → EB env vars. To rotate: update 1P, pipe to `gh secret set`, cut a patch release. To disable: `gh secret delete` the pair + patch release.
- **Release smoke test now requires direct-bypass → 401**. Any regression that silently drops ADR 024 enforcement will fail the next release loudly. The probe is at `release.yml` "Smoke test production" step.
- **`backend.addressr.io` sits behind Mountain Pass's Cloudflare zone** (not just AWS EB) — responses include `server: cloudflare` and `cf-ray: *-SYD`. Request path from RapidAPI: consumer → `addressr.p.rapidapi.com` (RapidAPI's CF + gateway) → `backend.addressr.io` (our CF + AWS EB). Two CF layers, each caching independently.
- **RapidAPI's edge honors origin `cache-control: max-age` but offers no client-side cache-bypass header and no documented provider purge**. Checked `docs.rapidapi.com/docs/gateway-configuration` and `rapidapi.com/guides/api-caching-with-http-headers` — neither covers cache control. Practical bypass mechanisms: query-string cachebust (CF includes query in cache key), origin-side short `max-age`, or a RapidAPI support ticket for purge. `Cache-Control: no-cache` from the client is ignored on free/pro CF plans.
- **Root `/` sets `cache-control: public, max-age=604800` (7 days)** at `src/waycharter-server.js` while its `Link` header evolves every release that adds/removes a rel. Consequence: the advertised HATEOAS contract can lag deployed code by up to 7 days at any CF edge (RapidAPI's or ours). P017 diagnosed this pattern: a v2.0.4 root response was still cached ~3 days into v2.2.0's life at RapidAPI's edge. Candidate fix not yet shipped — see problem backlog.
- **AWS resource-tag values reject commas** (`ValidationException: Invalid parameters provided to tagging operation`). Encountered on `module.opensearch_v2`'s `Adr = "029,030"` tag — replaced with `"029-030"`. Hyphen and `+ - = . _ : / @` are accepted; comma is not.
- **Uptime Robot 401s on `api.addressr.io` come from the Cloudflare Worker's referer/IP allowlist (ADR 018), NOT from ADR 024 origin enforcement (P040 corrected RCA).** `api.addressr.io` and `cool-bush-ca66.addressr-key-provider.workers.dev` both route through the same worker, so repointing between them changes nothing. The worker's 401 body is `no-origin not permitted from <ip>`; ADR 024's is `{"message":"Authentication required"}` — distinguish by body shape. Two compounding causes: (1) the worker's `safeIps.includes(srcIp)` is strict string-equality, so its CIDR entries never match anything; (2) UR's current published IP list has drifted significantly past the worker's hardcoded `safeIps`. Working workaround until the worker is patched: configure the UR monitor to send `Referer: https://addressr.io/` — that bypasses the IP allowlist via the worker's `safeHosts` path. Requires a UR plan that supports custom HTTP headers. Structural fix tracked in P042 (version-control the worker via Terraform per ADR 018 line 63).
- **GHCR image publishing: private-by-default, `GITHUB_TOKEN`-authed, and a `gh` token usually can't flip visibility.** The image publishes to `ghcr.io/mountain-pass/addressr` (note: hyphenated `mountain-pass` GHCR org vs unhyphenated `@mountainpass` npm scope — intentional, don't reconcile). CI auth is the built-in `GITHUB_TOKEN` with a `packages: write` permission grant — no external secrets; a reusable-workflow callee needs the CALLER's job to also grant `packages: write` (a callee's token scope can't exceed the caller's). First publish creates a **private** package; anonymous `docker pull` 401s until an org owner flips visibility to public (Package settings → Danger Zone, or the packages API). The default `gh` token (`repo`/`workflow`/`gist`/`read:org` scopes) can neither query nor change package visibility — that needs `read:packages`/`write:packages`, so it is a repo-owner action, not an agent one. Verify public anonymously with the ghcr token endpoint (no auth) → `GET /v2/<ns>/<img>/manifests/latest` == HTTP 200.
- **Terraform `required_version >= 0.13` rules out variable-level cross-variable validation** (that landed in TF 1.9). For pair-completeness guards (e.g. "both set or both empty"), use a resource-level `precondition` block, not `variable { validation {} }`.
- **`terraform validate` can't run locally** because the backend is Terraform Cloud (`app.terraform.io`). Local HCL syntax errors still surface; semantic/provider checks only run in CI. `terraform fmt -check -diff` is the best local-only sanity check.
