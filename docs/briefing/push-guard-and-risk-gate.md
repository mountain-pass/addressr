# Push Guard and the Risk Gate

The red-master push guard, its obsolete-run failure mode, and how the risk-scorer commit gate behaves at and above appetite. Split from `releases-and-ci.md` 2026-08-02 (Tier-3 budget rotation).

- **The red-master push guard blocks the very commit that fixes red master.** `push:watch` (and `git push` via the push-gate hook) refuses to push when master's latest CI run concluded `failure`. Historically escaped via `git push --no-verify origin master` for a CI-only fix — but that override was REMOVED by P377/RFC-029. See the obsolete-dispatch variant + current escape below.
- **The red-master push guard can be blocked by an OBSOLETE `workflow_dispatch` run you triggered earlier — and the escape is a fresh Release run, not `--no-verify`.** P377/RFC-029 removed the `ci-bypass` override, so `push:watch` hard-refuses to push when master's _latest_ CI run concluded `failure`. A manual `gh workflow run "Docker Image"` test that failed (e.g. a since-abandoned Docker Hub cred probe) becomes that latest red run and blocks an unrelated fix — the P052 deadlock via a stale dispatch. Escape (user-authorised 2026-07-28): trigger a fresh `gh workflow run "Release" --ref master`; with no changeset it only builds+tests (docker-publish and deploy both skip), concludes green, becomes the new latest run, and the gate clears.
- **The risk-scorer commit gate blocks commits at 6/25 or higher (appetite = 5).** Not discoverable until you hit it. Mitigation paths in the hook message: split the commit, add risk-reducing measures (`R1..Rn` suggestions in the scorer report), or — for a live incident — re-delegate to `wr-risk-scorer:pipeline` with incident context for a bypass marker. Adding one well-scoped Cucumber scenario frequently shaves 1-2 points and gets below appetite. **CAVEAT (2026-07-14): the `wr-risk-scorer:pipeline` AGENT mis-states this as "above appetite (>4)" and returns STOP on a residual of 5 — but the actual gate (`risk-gate.sh` parses `Threshold: 5` from RISK-POLICY.md, denies only `score > 5`) PASSES a 5.** So a 5/25 is WITHIN appetite; do NOT escalate it with a bypass or an AskUserQuestion. Only 6+ blocks. When the scorer says "above appetite" on a 5, restate it correctly and proceed.
- **The honest way past an above-appetite cutover is to EXERCISE the un-exercised scenario, not bypass it.** The v2→v3 cutover scored 8/25 because the scorer floored likelihood on "full-primary-concurrency untested" (read-shadow only mirrors low-volume reads). Running the ADR-031 k6 leg for real — local `addressr-server` pointed at the candidate domain over SigV4, sustained 20 VUs (0 failures, p95 368ms) — closed that exact gap and dropped the residual to 4 (within appetite) with no bypass. Reusable: when a score is driven by an un-exercised failure mode, run the test that exercises it.
