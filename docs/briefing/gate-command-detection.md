# How the Gates Detect the Command They Govern

The gates match on raw command TEXT, not on the tool's resolved invocation. Everything below follows from that. Split out of `external-comms-marker-mechanics.md` 2026-08-04 (Tier-3 budget). Tracked as P086, reported upstream as windyroad/agent-plugins#410.

## What You Need to Know

- **The heredoc delimiter must be literally `EOF`, and using any other one fails with a message that says the opposite of what happened.** The gate's extractor tries the heredoc form first with a pattern that hardcodes the word: `[<][<]\s*['\"]?EOF['\"]?\s*\n(.*?)\nEOF`. A perfectly ordinary `<<'ISSUEEOF'` does not match it, so extraction falls through to the `--body "([^"]*)"` capture, which truncates at the first quote inside the body. The marker is then keyed on that fragment while the reviewer's is keyed on the whole draft, and the gate re-blocks **after a clean PASS** saying the draft "has not been reviewed" — which is exactly wrong. Cost two filing round-trips on 2026-08-04 before the pattern was read. Always use `EOF`.

- **Documenting a governed command in a body trips the gate that governs it.** The detection regex matches the whole command string, and a heredoc body is part of that string, so a fenced code block whose lines begin `git push` or `git commit` reads as an invocation. Leading whitespace does not help — the pattern allows it. Prefix documented commands with `$ ` or another non-word character. This is the false-positive half of P086; the false-negative half is that wrapping a real invocation in `if`, `for` or a pipe means no gate fires at all.

- **Wrapping a governed command in any shell construct means NO gate fires.** The detection anchor is `(^|;|&&|\|\|)\s*<command>(\s|$)`, which catches the leading command in a compound statement and nothing else. Put `git push` or `git commit` after `if`, `then`, `do`, a pipe or `$( … )` and the hook exits 0: no score, no marker check, no CI precondition, no deny. Identical to the gate not being installed. Found accidentally on 2026-08-04 — a retry loop written to survive a flaky network pushed to master through a guard that had denied the same command minutes earlier. **The bypass needs no knowledge that it exists**, which is what makes it dangerous: a retry loop is the obvious response to a bad connection. Run governed commands as their own top-level statement.
