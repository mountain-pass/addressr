# Testing, TDD Hooks, and Code Structure

The TDD enforcement hook's matching rules, test anti-patterns, and the pre-commit tooling. Split from `what-will-surprise-you.md` 2026-07-28; the ESM/babel/toolchain half split out again to `babel-esm-and-toolchain.md` 2026-08-04 (Tier-3 budget).

- **The TDD enforcement hook only recognizes `*.test.*`/`*.spec.*` files — Cucumber `.feature` files don't trigger RED state.** Create a thin `.test.js` wrapper to enter the TDD cycle.
- **The TDD enforcement hook matches test files by basename, not co-location.** `service/foo.js` requires a `foo.test.mjs` (or `.test.js`, etc.) _somewhere_ the hook scans — e.g., `test/js/__tests__/foo.test.mjs` is recognised. Names that don't match basename-for-basename (e.g., `elasticsearch-mapping.test.mjs` for `client/elasticsearch.js`) are NOT recognised, and the hook will block edits with "no tests written for this file yet" even though tests exist. Rename the test file to the matching basename.
- **Pin the PROPERTY, not the implementation, or the pin blocks the fix it should have permitted.** `release-workflow-deploy-only.test.mjs` pinned `release-watch.sh` by asserting the literal jq fragments `select(.conclusion == "failure")` and `select(.name != "check-deps")`. Both were removed by a fix whose whole point was that testing for the literal `"failure"` is the defect — it lets `cancelled`, `timed_out`, `startup_failure` and an empty jobs array reach the green path. The pin went red on a correct change (P033 shape, on a guard rather than on product code). Rewritten to assert properties: the watch exit code is not discarded, the scan is default-deny, an empty scan exits non-zero, the advisory job stays exempt, and the known-bad selector cannot return. Two cautions. **Assert the ACT, not just the capture** — the first rewrite pinned that `--exit-status` was present and `|| true` absent, but nothing asserted the captured status was ever READ, so deleting that block passed every assertion. **Pin the exit, not the message** — `/UNKNOWN/` matches a branch that prints and then falls through; bound it to the `exit 1` as the loader-workflow pin does. Both holes were found by the risk scorer reviewing the pin, and the fix for the first was mutation-verified against a stripped mutant.

- **Test source-inspection is an anti-pattern in this codebase (P033).** `test/js/__tests__/address-service.test.mjs` regex-matches the source rather than executing the implementation. Tests pass even when behaviour is broken (e.g. the User-Agent fix was nearly shipped without verification). Behavioural test precedent set 2026-04-28 in `test/js/__tests__/gnaf-package-fetch.test.mjs` — mock fetch + cache via DI, assert the request was made with the expected header. Replace existing source-inspection tests opportunistically when touching the implementation.
- **Source-inspection tests that assert a path/token is ABSENT must strip comments first — in this repo the comment usually names the very thing being excluded.** House style documents _why_ a filter omits something directly above that filter, so `.github/workflows/docker-image.yml`'s push block explains its exclusion of `package.json` using the literal string `package.json`. A raw `!block.includes('package.json')` therefore fails against a correct file, and the obvious "fix" (loosening the assertion) would silently stop testing anything. Filter to structural lines only — e.g. `/^ {6}- '.+'$/` for a YAML path list — then compare parsed values. Pair it with self-preconditions (exactly one opener at the expected indent, non-empty result, a known-present entry asserted positively) so a mis-slice fails loudly instead of making every absence assertion pass vacuously.
- **Never use `git stash push` to mutation-test a tracked file — it silently unstages your staged set and leaves a stray stash entry.** The natural shape for verifying a source-inspection assertion actually bites is "break the file, run the test, restore it". Using `git stash push <path>` looks tidy and is a trap: the stash succeeds (so a `|| fallback` never fires), the file leaves the INDEX as well as the worktree, and a later `cp` from a backup restores the content but **not** the staging. Encountered 2026-07-27 mid-way through the ADR-040 stage-3 sequence: ADR-001 was staged, the mutation stashed it, and the restore looked clean while the commit would have shipped without it. Use a plain `cp` to `/tmp` and back, and re-run `git add` afterwards regardless. This repo carries four pre-existing stash entries from old commits, so a new stash@{0} is easy to miss.
- **lint-staged scratch-repo tests need `eslint.config.js`, `.prettierrc`, and non-empty seed files.** The era's eslint rule `unicorn/no-empty-file` will fail on a `touched.js` containing only a comment. Copy all three from repoRoot when staging a pre-commit replay; put real content in the seed.

- **A regex-based governance check fails OPEN on the rows it cannot parse, and says nothing.** The compendium badge check anchored its oversight capture to end-of-line, so any entry carrying a third field (`| **Supersedes:** ADR-NNN`) did not match and hit a silent `continue` — 6 of 43 entries unchecked, one of them wrong, while the test reported green. Two fixes, both general: **detect presence separately from parsing** (heading match, then badge parse) so an unparseable row cannot hide, and **count what you checked** — a check that cannot say how much it covered is the same fail-open shape it was written to catch.

- **A green run on a dirty tree is not evidence for any test whose oracle is git state.** `risk-register-invariants.test.mjs`'s review fence treats a modified file as "changed now", so a whole batch of dirty files passes by construction and reddens the moment it is committed. This is documented in the register itself and it still turned trunk red twice in one session on 2026-08-09 — once landing it, once "verifying" the fix from the same false green. The only evidence is a run against the committed state: commit locally (`git -c core.hooksPath=/dev/null commit`), re-run, and only then push. Mutation-test the same way — throwaway commit, observe, `git reset --hard` to a captured SHA. Note that `git checkout -- <path>` inside a mutation loop destroys uncommitted work in that file; back up to `/tmp` and restore from there instead.

- **A test that newly imports a source module can pull in a GENERATED file that no test tier creates.** `src/waycharter-server.js` imports `../version.js`, which `genversion` writes at `prepack` and `.gitignore` excludes. The first `test:js` case to import that module passed locally — a previous pack had left the file — and failed all three CI jobs on a clean checkout with `ERR_MODULE_NOT_FOUND`. Fixed by giving the tier its own prerequisite (`pretest:js` → `genversion`) rather than by making the test tolerate absence, because a test that skips on a missing prerequisite hides exactly this. Reproduce before believing a fix: delete the generated file and run the tier.
