## What You Need to Know

- **Migrating OpenSearch again? Read `docs/OPENSEARCH-MIGRATION-PLAYBOOK.md` FIRST.** It distills the blue/green migration into a reusable, gated checklist + the expensive learnings. Two full runs are now complete: 1.3.20→2.19 (Phase 1, 2026-07-10) and 2.19→3.5 (Phase 2, 2026-07-14). Key ones: sizing is empirical — re-measure warm parity on the new engine (3.5 held parity at m6g.large × 2, but don't assume for the next major); and the cutover risk-gate wants the full-primary-concurrency scenario _exercised_ pre-cutover, not just read-shadowed — run k6 against the candidate domain AS primary (local server → candidate over SigV4) to lower the scorer's likelihood honestly rather than forcing a bypass.
- **Prod search behaviour is directly smoke-testable from this repo**: `.env` carries `RAPIDAPI_KEY`; `curl -H "X-RapidAPI-Key: $RAPIDAPI_KEY" -H "X-RapidAPI-Host: addressr.p.rapidapi.com" "https://addressr.p.rapidapi.com/addresses?q=<query>"` exercises the full prod path (gateway → EB → OpenSearch). Used 2026-07-19 for the P027 close battery (8 ranking/fuzziness queries). Note the connected addressr MCP server has NO search tool (only get-by-URL + health), and its key is a different, unsubscribed account — use the `.env` key via curl instead.
- **Production runs the v2 API** (`addressr-server-2`, waycharter-based HATEOAS). NOT the v1 swagger-tools API. See `deploy/deploy.sh` line 22.
- **Single v2 API only — v1 Swagger API fully removed in v3.0.0 (ADR-036, 2026-07-17).** `swagger.js`, `server.js`, `controllers/`, `bin/addressr-server.js`, `api/swagger.yaml`, and the `swagger-tools` dependency are gone. Only `addressr-server-2` remains. CI runs three v2 profiles: `nodejs` (in-process `embedded2` tier — drives the real waycharter app via `@mountainpass/waychaser`'s pluggable fetch + `light-my-request`, no socket), `rest2`, and `cli2`.
- **Two backends behind RapidAPI**: `backend.addressr.io` and `backend2.addressr.io`, round-robin load balanced. A Cloudflare Worker (`cool-bush-ca66`) proxies requests from addressr.io and Uptime Robot, injecting a RapidAPI API key.
- **Production OpenSearch is 3.5** (AWS managed, `addressr5` domain, m6g.large.search × 2, IAM/SigV4 per ADR 033) as of the **2026-07-14 cutover + decommission** (ADR 035 Phase 2). `addressr5` is the SOLE remaining domain — both `addressr3` (v1/1.3.20, decommissioned 2026-07-11) and `addressr4` (v2/2.19, decommissioned 2026-07-14) are gone. Rollback is now rebuild-from-G-NAF (hours), NOT an instant flip to a warm standby — the accepted ADR-035 Option C trade (avoids ~$3.6k–7.2k/multi-year parallel-domain cost). The 9 quarterly `update-{state}.yml` crons all target `v3` over GitHub-OIDC/SigV4 (`gha-v3-loader` role). **The 2.19 leg is retained ONLY in the `release.yml` CI matrix** (`['2.19.5','3.5.0']`) as a code-compatibility + regression target until AWS EOLs 2.19 — it is not running infrastructure. In-cutover zero-outage still holds via the EB rolling deploy + `/health` auto-rollback.
- **The EB primary SigV4 config EMPTIES `ELASTIC_USERNAME`/`ELASTIC_PASSWORD`, not just sets `ELASTIC_AUTH_MODE=sigv4`.** `buildClientNode` (`src/client-node-url.js:20`) omits embedded creds only when username is empty, giving the credential-less node URL the SigV4 signer wraps. Leaving basic creds set alongside sigv4 is an untested config (embedded-userinfo + signer). The cutover EB block: `ELASTIC_HOST=module.opensearch_v2.endpoint`, `ELASTIC_AUTH_MODE=sigv4`, `ELASTIC_REGION=ap-southeast-2`, `ELASTIC_USERNAME=""`, `ELASTIC_PASSWORD=""`.
- **`/health` now pings OpenSearch (503 when unreachable) — a static health check silently breaks zero-outage auto-rollback.** Pre-2026-07-10 `/health` returned 200 without touching the backend, so a misconfigured backend cutover would pass health, roll out fleet-wide, and NOT trigger EB's `RollbackLaunchOnFailure`. `src/es-health.js` (`checkEsHealth`/`checkEsHealthCached`) now `ping()`s the app's `globalThis.esClient`; 503 → EB marks unhealthy after `UnhealthyThreshold=5 × 10s ≈ 50s` → auto-rollback. `HEALTH_ES_PROBE=off` reverts to always-200 (ops kill-switch); a ~5s TTL cache bounds anonymous ping-amplification (`/health` is on the ADR 024 unauth allowlist). General lesson: a deploy-gating health check MUST exercise the dependency it's protecting, or the auto-rollback is theatre.
- **A cutover repoints the SERVING path but you must ALSO repoint every WRITE/refresh consumer.** The 2026-07-10 v2 cutover flipped the EB read path to v2 but the 9 quarterly loader crons kept writing v1 — production read v2 while v2's data silently froze (nothing refreshes it) and v1 (unread) kept getting fresh data. The architect caught this before the v1 decommission. When cutting over a backend, enumerate ALL consumers (serving reads, loaders/refreshers, dashboards, alarms), not just the request path.
- **Confirmed ADRs can slip un-ratified and block dependent work mid-flight.** ADR 030 (Terraform-managed domain) was never `human-oversight: confirmed`; the cutover (whose `ELASTIC_HOST=module.opensearch_v2.endpoint` is literally ADR 030's completing act) was blocked by the architect until 030 was ratified. Pattern: before building on an ADR, check its frontmatter carries `human-oversight: confirmed` — the drain is `/wr-architect:review-decisions`. (Ratified 029/030/031/033 all confirmed now.)
- **OpenSearch 2.19 needs replicas=0 + larger EBS for a from-scratch bulk load on t3.small.** The 2.19 engine uses ~1.7× the disk-per-doc of 1.3.20; a from-scratch 16.9M-doc load node-drops (and can silently delete the index — P035) on t3.small×2/12GB. Load with a `number_of_replicas: 0` index template + 20GB EBS (halves disk + write pressure), then set replicas=1 after the load and let the replica build to green. The t3.small class SERVES 16.8M fine (v1 proves it) — the wall is the from-scratch load pattern, not steady-state serving.
- **The SigV4 read-shadow mirror adds only ~0.44ms p95 to the primary thread.** Measured 2026-07-08 (`scratchpad/shadow-primary-delta.mjs`, 2000 warmed iters): shadow-off p95 0.001ms, shadow-on-SigV4 p95 0.438ms. `mirrorRequest` is fire-and-forget and SigV4 signing runs in the async connection layer AFTER it returns, so signing barely touches the synchronous primary path — this is why the ADR 031 ≤1ms invariant holds with SigV4 on. Re-run this micro-measure (it's more reliable than a k6 delta against a hundreds-of-ms baseline) if the shadow client changes before cutover.
- **Dockerfile upgraded to Node 22-alpine + v2 CMD** (P001 fix, commit 1a68e6e; verification pending). The old "stale Node 16" note is obsolete — don't cite it as a CVE source.
- **npm audit is now 0 (2026-07-18, P030 resolved across v3.0.0 + v3.0.1).** The swagger-tools prod line went with the v1 removal (v3.0.0); the last 20 dev-only findings were cleared in v3.0.1 by removing three unused/abandoned packages — `istanbul-middleware` + `istanbul` (dead; coverage uses `nyc`) and `npm-check` (abandoned since ~2020, rooted the critical lodash + tmp/got/inquirer). `npm-check` was replaced with maintained `depcheck` (unused-dep detection) + `npm-check-updates`/`ncu` (scripts `deps:unused` / `deps:outdated` / `deps:update`). Do NOT "remove" a vulnerable dep by repointing its scripts to `npx` — that hides it, doesn't fix it (user correction).

- **waychaser v5 migration complete** (v2.0.0). waycharter convenience API (`registerCollection` with `itemPath`/`itemLoader`) works well for new endpoints.
- **Two OpenSearch indices**: `addressr` (addresses, ~15M docs) and `addressr-localities` (localities, ~16k docs). Both use the same custom analyzer pipeline. Locality postcodes are derived from ADDRESS_DETAIL during loading (ADR 022).

- **35 ADRs exist** in `docs/decisions/` documenting all major architectural choices (OpenSearch, dual API, EB deployment, HATEOAS, RapidAPI, Cloudflare Worker, locality postcode derivation, search ranking, range-address expansion, fuzziness tuning, OpenSearch upgrade + Terraform-managed domain, read-shadow, OIDC loader, 3.5 upgrade, etc.). The OpenSearch-upgrade arc is now all accepted: ADR 029 (two-phase blue/green), 030 (Terraform-managed domain), 031 (read-shadow), 033 (SigV4), 034 (OIDC quarterly loader), and 035 (3.5 upgrade + retain 2.19 as CI regression). Regenerate the compendium with `wr-architect-generate-decisions-compendium` after any ADR status change.
- **Australian range-addresses are endpoints-only, not interpolated.** G-NAF `NUMBER_FIRST` / `NUMBER_LAST` (e.g., `103-107`) are the two actual addresses of the property; `104`/`106` are typically on the opposite side of the street under AU addressing convention, and `105` is not provably part of the property without authoritative interpolation data. ADR 028 captures this — `sla_range_expanded` emits exactly `[first, last]` aliases, not the full range. Confirmed by user correction after ADR 026's full-interpolation shipped in v2.3.0 and produced false positives.
- **Search fuzziness is `AUTO:5,8` (not default `AUTO`) on bool_prefix.** 3-4 digit numeric tokens (street numbers, postcodes) require exact match; 5+ char typos still fuzz. ADR 027. Known partial exception: P027 — synonym-expanded short-form street-type tokens (e.g. `Rd`) in non-last position bypass this on OpenSearch 1.3.20.
