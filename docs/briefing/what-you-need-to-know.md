## What You Need to Know

General project facts. OpenSearch topology + cutover mechanics split to [opensearch-and-deploy-state.md](./opensearch-and-deploy-state.md) on 2026-07-28 (Tier-3 budget).

- **Prod search behaviour is directly smoke-testable from this repo**: `.env` carries `RAPIDAPI_KEY`; `curl -H "X-RapidAPI-Key: $RAPIDAPI_KEY" -H "X-RapidAPI-Host: addressr.p.rapidapi.com" "https://addressr.p.rapidapi.com/addresses?q=<query>"` exercises the full prod path (gateway → EB → OpenSearch). Note the connected addressr MCP server has NO search tool (only get-by-URL + health), and its key is a different, unsubscribed account — use the `.env` key via curl instead.
- **Production runs the v2 API** (`addressr-server-2`, waycharter-based HATEOAS). NOT the v1 swagger-tools API. See `deploy/deploy.sh` line 22.
- **Single v2 API only — v1 Swagger API fully removed in v3.0.0 (ADR-036, 2026-07-17).** `swagger.js`, `server.js`, `controllers/`, `bin/addressr-server.js`, `api/swagger.yaml`, and the `swagger-tools` dependency are gone. Only `addressr-server-2` remains. CI runs three v2 profiles: `nodejs` (in-process `embedded2` tier), `rest2`, and `cli2`.
- **Confirmed ADRs can slip un-ratified and block dependent work mid-flight.** ADR 030 (Terraform-managed domain) was never `human-oversight: confirmed`; the cutover was blocked by the architect until 030 was ratified. Pattern: before building on an ADR, check its frontmatter carries `human-oversight: confirmed` — the drain is `/wr-architect:review-decisions`.
- **The published Docker image is Distroless (ADR-039) and published to `ghcr.io/mountain-pass/addressr` (ADR-040, 2026-07-28).** No shell/package-manager/npm in the runtime; `tini` is PID 1; graceful SIGTERM shutdown handler added (P067). Any "stale Node 16 / Node 22-alpine" note is obsolete — do not cite it as a CVE source. Publishing details in [deploy-infra-and-caching.md](./deploy-infra-and-caching.md).
- **npm audit is now 0 (2026-07-18, P030 resolved across v3.0.0 + v3.0.1).** The swagger-tools prod line went with the v1 removal; the last dev-only findings were cleared by removing `istanbul-middleware` + `istanbul` (dead; coverage uses `nyc`) and `npm-check` (abandoned), replaced with `depcheck` + `npm-check-updates`/`ncu`. Do NOT "remove" a vulnerable dep by repointing its scripts to `npx` — that hides it, doesn't fix it (user correction). (Note: `check-deps` may show a separate moderate `@hono/node-server` transitive advisory with no upstream safe fix yet — tracked separately.)
- **Trunk-based development per DORA.** No branch protection rules. Risk management is via the hook-based risk scoring system, not server-side gates.
- **Revenue-generating service.** Paid and free-tier consumers on RapidAPI. Business metrics are confidential — never commit user counts, revenue, pricing, or traffic volumes to the repo.
- **Babel transpilation is tech debt.** Node 22 has native ESM but the project still uses Babel. See ADR 005.
- **Credentials**: production OpenSearch creds in `.env`, AWS + Cloudflare creds in `~/.profile`. Use these for debugging production — never commit them.
- **npm version mismatch**: Local runs Node 25 / npm 11, CI uses Node 22 / npm 10. Always regenerate lockfiles with `npx -y npm@10 install` before committing.
- **waychaser v5 migration complete** (v2.0.0). waycharter convenience API (`registerCollection` with `itemPath`/`itemLoader`) works well for new endpoints.
- **addressr.io website** is a separate Gatsby project on Netlify at `../addressr.io/`. It calls the API via the Cloudflare Worker.
- **ADRs live in `docs/decisions/`** documenting all major architectural choices. ADR 026 is superseded by ADR 028. The OpenSearch-upgrade arc is all accepted: ADR 029 (two-phase blue/green), 030 (Terraform-managed domain), 031 (read-shadow), 033 (SigV4), 034 (OIDC quarterly loader), 035 (3.5 upgrade). The release-pipeline arc: ADR 039 (Distroless), 040 (change-type→action matrix + GHCR). The compendium (`docs/decisions/README.md`) is refreshed by a hook on every ADR edit — do NOT run the generator manually (see [external-comms-and-compendium.md](./external-comms-and-compendium.md)).
- **Australian range-addresses are endpoints-only, not interpolated.** G-NAF `NUMBER_FIRST` / `NUMBER_LAST` (e.g., `103-107`) are the two actual addresses of the property; `104`/`106` are typically on the opposite side of the street under AU addressing convention. ADR 028 — `sla_range_expanded` emits exactly `[first, last]` aliases, not the full range. Confirmed by user correction after ADR 026's full-interpolation shipped in v2.3.0 and produced false positives.
- **Search fuzziness is `AUTO:5,8` (not default `AUTO`) on bool_prefix.** 3-4 digit numeric tokens (street numbers, postcodes) require exact match; 5+ char typos still fuzz. ADR 027. Known partial exception: P027 — synonym-expanded short-form street-type tokens (e.g. `Rd`) in non-last position bypass this on OpenSearch 1.3.20.
